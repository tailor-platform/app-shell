# State → action matrix

Each in-scope discussion (for the active component) is classified into exactly
the states below, by re-deriving from the live sources (no stored state). A
discussion can be in more than one (e.g. unlinked _and_ its match already
shipped) — handle the earliest applicable linkage state first, then fall through
to milestone/release. Throughout, `LABEL` = the component's `label`,
`MILESTONE_PREFIX` = its `milestone_prefix`, `RELEASE_TAG_PREFIX` = its
`release_tag_prefix` on `release_repo`.

Gate: **auto** = apply + report; **approval** = queue for the operator; **flag** =
list only, never act. A **flag** row may still carry an approval-gated proposal
(e.g. a `status:` label): the row is surfaced for a human, and — per the
authorization policy — **every `status:` label change is approval-gated**, never
auto-applied.

> **Lifecycle gate.** The Milestone and Release sections below apply only when
> the component file defines `milestone_prefix` + `release_repo` +
> `release_tag_prefix`. When those are empty, skip both sections and report the
> milestone/release dimension as _not configured_ for that component.

## Linkage — does a ticket exist, is it linked?

| State                                                    | Detected by                                                                                                                                                                                                                                                                                                                                                           | Action                                                                                                                                                                                                                                                                                | Gate                                              |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| **Reply hints at a non-ticket disposition**              | a maintainer reply signals by-design, an existing workaround/alternative ("use X"), belongs to another component, awaiting author info, or won't-do                                                                                                                                                                                                                   | do **not** propose a ticket; surface the hint and route (needs-info / wontfix / out-of-scope)                                                                                                                                                                                         | flag; a `status: needs-info` proposal is approval |
| No matching ticket, actionable (bug/request)             | in scope, no link comment, board search finds nothing, `Feedback Type` is `Feature Request` (the form's literal; see team-ps/platform-feedback/references/post-template.md), **no reply already sets a non-ticket direction, and the feature is not already shipped** (verified against release notes + codebase — see reconcile.md → Already-addressed verification) | summarise + propose a new ticket (filed via [../../pf-feedback-triage/references/issue-template.md](../../pf-feedback-triage/references/issue-template.md) + [project-routing.md](../../pf-feedback-triage/references/project-routing.md)); on creation, link it and set `pf-triaged` | approval (ticket + comment)                       |
| No ticket, not actionable (question / idea / discussion) | `Feedback Type` is `General Feedback` or `Pain Point` (the form's literals), OR category is Q&A/Ideas                                                                                                                                                                                                                                                                 | list under _needs a human_; optionally propose `status: needs-info`; do **not** file                                                                                                                                                                                                  | flag; a `status: needs-info` proposal is approval |
| Ticket exists, discussion **unlinked**                   | board match found, no comment/body references it                                                                                                                                                                                                                                                                                                                      | propose link comment; set `pf-triaged`; backfill `Source discussion:` on the ticket                                                                                                                                                                                                   | approval (comment); auto (`pf-triaged`, backfill) |
| **Several** candidate tickets                            | >1 plausible board match                                                                                                                                                                                                                                                                                                                                              | list candidates in the digest for the operator to pick                                                                                                                                                                                                                                | flag                                              |
| Ticket exists and **linked**                             | a comment/body references the ticket                                                                                                                                                                                                                                                                                                                                  | in sync → fall through to milestone/release checks                                                                                                                                                                                                                                    | —                                                 |

## Milestone — earmarking (ticket is linked; lifecycle enabled)

| State                                             | Detected by                                                                 | Action                                                                        | Gate     |
| ------------------------------------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | -------- |
| Ticket newly milestoned `<milestone_prefix>X.Y.Z` | milestone set; no operator earmark comment names a version                  | propose earmark comment for vX.Y.Z                                            | approval |
| Milestone **changed** since last earmark          | milestone version ≠ version parsed from the latest operator earmark comment | propose "moved to vX.Y.Z (was vA.B.C)" comment                                | approval |
| Milestone **removed** after an earmark            | earmark comment exists; ticket now has no milestone                         | list under _needs a human_ — never walk back a customer promise automatically | flag     |

## Release — announcing (lifecycle enabled)

| State                                                      | Detected by                                                                                                                                                                                                                                                                                        | Action                                                                                                   | Gate                                             |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| Linked ticket's version **shipped**, discussion not told   | a **published** release `<release_tag_prefix>X.Y.Z` exists for the ticket's milestone (a closed milestone alone is weaker corroboration, not sufficient); **no operator release comment** (presence of comment is the gate; the `status: resolved` label may have been applied by another process) | propose release comment + `status: resolved`                                                             | approval                                         |
| **New** discussion matches an **already-shipped** ticket   | match found; ticket Done / released                                                                                                                                                                                                                                                                | propose one combined comment: link + "already addressed in vX.Y.Z"                                       | approval                                         |
| **New** discussion, no ticket, but feature already shipped | no link comment, no ticket match, yet the already-addressed check (release notes + codebase) confirms it's shipped                                                                                                                                                                                 | same as above — propose "already addressed in vX.Y.Z" + `status: resolved`; do **not** file a new ticket | approval                                         |
| Ticket closed as **wontfix**                               | ticket `stateReason == NOT_PLANNED` or a `wontfix` label — **not** merely closed-without-release (a completed-but-unreleased ticket is shipped-pending, not wontfix)                                                                                                                               | list under _needs a human_; optional wontfix note + `status: wontfix`                                    | flag; the `status: wontfix` proposal is approval |
| Ticket Done but **no milestone** — version unknown         | closed, milestone empty, can't name the release                                                                                                                                                                                                                                                    | list under _needs a human_                                                                               | flag                                             |

## Hygiene — drift the sweep should also catch

The two milestone-staleness rows below are lifecycle-only (same gate as the
Milestone/Release sections above).

| State                                                | Detected by                                                                                                                                                                                                                                                                                        | Action                                                                                                                                                                                                               | Gate                                        |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| Status-label drift                                   | discussion `status:*` disagrees with ticket state                                                                                                                                                                                                                                                  | propose label change                                                                                                                                                                                                 | approval                                    |
| `pf-triaged` drift                                   | linked but not `pf-triaged` (or `pf-triaged` with no findable ticket)                                                                                                                                                                                                                              | set / remove `pf-triaged` (or flag if no ticket)                                                                                                                                                                     | auto / flag                                 |
| Missing forward link                                 | linked, but the ticket body contains **no** discussion reference at all — match `knowledge/discussions/(\d+)`, never a marker string like `Source discussion:` (`pf-feedback-triage` writes `**Source:** <url>`; legacy tickets use `### Discussion` or a bare URL — all of those count as linked) | backfill with `**Source:** <url>` so future runs are reliable                                                                                                                                                        | auto                                        |
| Milestone **stale vs release notes** — closed ticket | ticket closed/completed, milestone names vA.B.C, but release notes show the feature actually shipped in a different vX.Y.Z (reconcile.md → Milestone reconciliation)                                                                                                                               | propose correcting the milestone to the true shipped vX.Y.Z (create the milestone first if it doesn't yet exist)                                                                                                     | approval                                    |
| Milestone **stale vs release notes** — open ticket   | ticket open, milestone names a version that has **already been published** as a release (so the feature can't have shipped there)                                                                                                                                                                  | if the work is merged-but-unreleased (in codebase / has a pending changeset), propose re-targeting to the next unreleased version; if genuinely unimplemented, release notes can't name a version → flag for a human | approval (re-target) / flag (unimplemented) |
| Linked ticket is a **duplicate**                     | ticket `stateReason == DUPLICATE` or `duplicate` label                                                                                                                                                                                                                                             | resolve the canonical (reconcile.md query 8), **re-point the discussion at the canonical ticket**, then re-derive state from the canonical (it may itself be earmark-due or release-due)                             | approval (re-link comment)                  |
| Duplicate with **unresolvable** canonical            | duplicate, but no `MarkedAsDuplicateEvent` and no parseable `duplicate of #N`                                                                                                                                                                                                                      | flag for a human to name the canonical                                                                                                                                                                               | flag                                        |
| Stale link (transferred / deleted)                   | linked ticket no longer resolvable                                                                                                                                                                                                                                                                 | flag, propose re-link                                                                                                                                                                                                | flag                                        |
| One ticket ↔ **many** discussions (or vice-versa)    | fan-out in the link mapping                                                                                                                                                                                                                                                                        | on earmark/release, propose the comment on **every** linked discussion                                                                                                                                               | per underlying action                       |
| Regression / reopened                                | resolved discussion gets a new author reply, **or a linked ticket is reopened while the discussion is `status: resolved`**                                                                                                                                                                         | propose reverting `status: resolved`; never auto-act                                                                                                                                                                 | flag; the revert is approval                |
| Out-of-scope fuzzy hit                               | classifier says "merely uses the component" or low confidence                                                                                                                                                                                                                                      | list under _needs a human_; do not label/file                                                                                                                                                                        | flag                                        |
| Locked / answered discussion                         | discussion `locked`, or a Q&A marked answered (`isAnswered`)                                                                                                                                                                                                                                       | reconcile labels only; no public comment                                                                                                                                                                             | —                                           |
| Duplicate discussions                                | two discussions describe the same thing                                                                                                                                                                                                                                                            | flag for dedupe (`duplicate` label)                                                                                                                                                                                  | flag                                        |

## Idempotency reminder

Because state is re-derived every run, the guard against double-posting is
simply: **check the discussion's comments before proposing anything.** If a
comment already covers the action (link present, earmark for the current version
present, release announced), do nothing. Only the earmark needs the version
parsed out of the prior comment (see reconcile.md → State detection).
